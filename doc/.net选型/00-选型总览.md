# Sail Nora .NET 选型总览

> 状态：生效 · 日期：2026-11-10  
> 方向调整：**整体后端范式对齐已建项目 sleveen-admin**；ORM / AI / 定时任务 / 基础权限与 JWT 按下文钉死。  
> 决策 ADR：[ADR-0003](../ADR/0003-dotnet选型与sleveen-admin对齐.md)  
> 产品目标仍见 [全局总任务纲领](../00-全局总任务纲领.md)；本文件约束**实现栈与平台层形状**。

---

## 1. 方向调整（相对早期草案）

| 主题 | 早期倾向 | **现行决定** |
|------|----------|--------------|
| 后端范式 | 自研 ASP.NET 分层，偏 WeKnora Go 镜像 | **整体参考 sleveen-admin**（Foundation / System / Host、配置分片、Scrutor、ApiResult 等） |
| ORM | EF Core + 原样 SQL runner | **mooSQL（mooSQL.Ext）** |
| 后台 / 定时任务 | 自研对齐 asynq 的 Redis 队列 | **Hangfire**（优先 **Hangfire.MooSql**，复用主库 + 表前缀） |
| AI 基建 | 自研 Provider + 可选 MEAI；Agent 全自研 | **MAF（Microsoft.Agents.AI）** 为 AI 基建；产品 Agent/RAG 在其上扩展 |
| 基础权限 / 接口 / JWT | 复刻 WeKnora 鉴权矩阵与响应形 | **与 sleveen-admin 一致**（JWT Bearer、RefreshToken、Permission、ApiResult） |

## 2. 与 sleveen-admin 的对齐范围

参考实现：`sleveen-admin` 的 `backend/core`（`Foundation` / `System` / `Web.Api` / `Business`）及文档 `PLAN.md`、`doc/mooSQL-integration.md`。

### 2.1 必须对齐（平台层）

| 项 | sleveen-admin 做法 | sail-nora 要求 |
|----|-------------------|----------------|
| JWT | `JwtBearer` + `JwtOptions`；过期/未授权走 `ApiResult` | **同模式**：签发、校验、Challenge 写 JSON 失败体 |
| RefreshToken | 轮换 + Hangfire 清理作业 | **同能力** |
| 权限 | `[Permission]` + `PermissionAuthorizationHandler` + PolicyProvider | **同模型**（按钮/策略码）；WeKnora 空间 RBAC 在业务域映射到此模型或扩展 Claims |
| 统一接口包装 | `ApiResult` / `ApiResultAttribute` / 全局异常过滤 | **同形状**（`Code` / `Msg` / `Data`） |
| DI | Scrutor 扫 `*Service`；业务**具体类**，禁止空转发 `IXxx`+`Impl` | **同约定**；跨层可替换点才用接口 |
| 配置 | `Configuration/*.json` 分片（Jwt、DB、Hangfire、Ai、Redis…） | **同分片思路**；可另加 WeKnora env 别名绑定 |
| 数据访问 | mooSQL + `MooRepository<T>` / `[SooTable]` | **同 ORM** |
| 定时与后台 | Hangfire.AspNetCore + Hangfire.MooSql（`hf_` 前缀） | **同栈** |
| AI 入口 | `Microsoft.Agents.AI` + OpenAI ChatClient；SSE 流式 | **同基建（MAF）** |

### 2.2 分层借鉴（不必抄仓名）

```text
Host（cmd/server）     ← Program / JWT / CORS / Hangfire Dashboard / 中间件
Foundation             ← ApiResult、mooSQL 封装、JWT 工具、DI 标记
System / Platform      ← 用户、角色、权限、组织/空间、字典、文件、审计…
Application / Product  ← 知识库、RAG、Agent、Wiki、数据源…（WeKnora 产品域）
```

物理目录仍服从 [ADR-0002](../ADR/0002-src目录与上游对齐.md)：重写代码在 `src/cmd`、`src/internal`；项目文件可按 Foundation/System/Product 聚合，**路径尽量对照上游包**。

### 2.3 不强制对齐

| 项 | 说明 |
|----|------|
| 前端壳 | sail-nora 产品 UI 仍以 `src/sync/frontend`（WeKnora Vue/TDesign）为主；**不**默认换成 Soybean/Element |
| YARP / 无界门户 / Sailflow | sleveen-admin 产品能力，非 WeKnora 对等物；按需后期引入 |
| SignalR 在线用户 | 非 WeKnora 必需；沙箱终端等仍优先 WebSocket/SSE 产品契约 |
| 主键 Guid v7 / `Su_` 前缀 | admin 惯例；WeKnora 表结构以 `src/sync/migrations` 为准时，**表与主键跟随上游 SQL**，mooSQL 只做访问层 |

## 3. 钉死选型详表

### 3.1 运行时与宿主

| 项 | 选型 |
|----|------|
| TFM | `net8.0;net10.0;net11.0`（ADR-0001）；日常开发可对齐 admin 主力 **net10** |
| HTTP | ASP.NET Core Controllers（与 admin 一致）+ 必要时 Minimal 端点 |
| 日志 | MEL；建议 Serilog 结构化（admin 可增强对齐） |
| 缓存 | StackExchange.Redis（与 admin 一致） |

### 3.2 ORM：mooSQL

| 项 | 选型 |
|----|------|
| 包 | **mooSQL.Ext**（优先与 sleveen-admin 相同的源码 ProjectReference 方式） |
| 封装 | 借鉴 `MooSqlSetup` / `MooRepository<T>` |
| 实体 | `[SooTable]` / `[SooColumn]` |
| 方言 | 开发可用 SQLite；生产对齐 WeKnora 以 **PostgreSQL** 为主；配置切换同 admin「改 DbType / 连接串」 |
| 与上游迁移 | **优先执行 `src/sync/migrations` SQL** 保证表结构；mooSQL 映射已有表。禁止只靠 EF 式迁移另起一套 schema |
| 向量检索 | 仍通过 SQL / 各向量引擎 SDK；不经由「换 ORM」解决 |

### 3.3 任务：Hangfire

| 项 | 选型 |
|----|------|
| 框架 | **Hangfire.AspNetCore** |
| 存储 | **Hangfire.MooSql**（复用主库，表前缀如 `hf_`，配置项对齐 admin） |
| 用途 | 定时任务（自动化、清理、同步 cron）+ **文档处理等后台 Job** |
| 与 WeKnora 任务名 | 用 Job / Queue 名或参数保留上游语义（如 `document:process`），便于对照与运维面板；**不**再实现 asynq 兼容层为默认路径 |
| Dashboard | 对齐 admin：受权访问；可关 `Hangfire:Enabled` |
| Lite 无 Redis | Hangfire 走 MooSql 主库即可；无独立 Redis 队列依赖（Redis 仍可用于缓存/SSE 缓冲） |

### 3.4 AI 基建：MAF

| 项 | 选型 |
|----|------|
| 框架 | **Microsoft.Agents.AI（MAF）** + `Microsoft.Agents.AI.OpenAI`（版本随 admin / 现行包升级） |
| 底层 | OpenAI 兼容 `ChatClient`（自定义 Endpoint / ApiKey，同 admin `Ai` 配置分片） |
| 流式 | Agent `RunStreamingAsync` → SSE（admin `/api/ai/chat` 模式可参考） |
| RAG / 工具 | 在 MAF Agent 上挂 **知识检索、读文档等 Function/工具**；事件与进度需满足产品前端时，在流式适配层翻译 |
| Embedding / Rerank | MAF 之外用 HttpClient 或 MEAI 抽象补齐；注册表模式对齐 WeKnora 多厂商 |
| 禁止 | 以 Semantic Kernel 整栈替换 MAF 作为默认基建（可局部参考，不作主线） |

### 3.5 基础权限、接口、JWT（= sleveen-admin）

| 项 | 选型 |
|----|------|
| 认证 | `Microsoft.AspNetCore.Authentication.JwtBearer` |
| 令牌 | Access + Refresh 轮换；SigningKey / Issuer / Audience 配置分片 |
| 授权 | `[Authorize]` + `[Permission("…")]`；超管旁路同 admin |
| 响应 | `ApiResult` / `ApiResultCodes`；401 Challenge 返回 JSON |
| 登录注册等 | Controller + `*Service` 具体类；验证码等可按需从 admin 裁剪引入 |
| WeKnora API Key / Embed / MCP 端点令牌 | **产品集成能力**，在平台 JWT 之上另做 Handler/中间件；不替代平台登录主路径 |

### 3.6 其它（保持或收紧）

| 项 | 选型 |
|----|------|
| docreader | Grpc.Net.Client，调用 `src/sync/docreader` |
| 对象存储 | S3 兼容 SDK 等，按空间可插拔 |
| 检索引擎 | pgvector / ES / Qdrant… 注册表 |
| MCP | Streamable HTTP；C# SDK 或自研薄封装 |
| 可观测 | OTel；Langfuse 钩子挂 Agent/Pipeline |
| 测试 | xUnit + WebApplicationFactory；产品 SSE 另做黄金集 |

## 4. 与 WeKnora 产品契约的关系

纲领仍要求能力对齐 WeKnora（RAG / Agent / Wiki 等）。选型调整后分层如下：

```text
┌─────────────────────────────────────────────┐
│  src/sync/frontend（WeKnora UI）             │
│  产品 API：知识库 / 对话 SSE / Agent 事件…   │  ← 尽量保持路径与事件兼容
├─────────────────────────────────────────────┤
│  适配 / 产品 Controller（internal/handler） │
├─────────────────────────────────────────────┤
│  平台层（JWT / Permission / ApiResult）      │  ← 与 sleveen-admin 一致
│  mooSQL · Hangfire · MAF                    │
└─────────────────────────────────────────────┘
```

| 层级 | 兼容目标 |
|------|----------|
| 平台登录与权限管理 UI | 若继续用 WeKnora 登录页，需 **适配层** 把 admin 式 JWT/ApiResult 转成前端期望；或后续评估管理端与产品端分离。**平台实现本身不复刻 Go 鉴权细节为第一原则** |
| 知识问答 / Agent SSE | **优先兼容** `src/sync/frontend` 已有 SSE 消费逻辑 |
| 表结构 | **优先** `src/sync/migrations` |
| 后台任务语义 | Hangfire Job 覆盖原 asynq 任务职责，名称可对照 |

差异表与适配清单在后续 `doc/02-API契约与兼容性.md` 维护。

## 5. Go 功能域 → .NET 落点（更新）

| WeKnora Go 域 | .NET 落点 |
|---------------|-----------|
| `middleware` 鉴权 / RBAC | Foundation + Permission（admin 范式）+ 产品 API Key/Embed 扩展 |
| `handler` / `router` | Controllers；路由分组可保留 `/api/v1` 产品前缀 |
| `application/*` | Product/Application Services（具体 `*Service`）+ mooSQL Repo |
| `models` + Agent LLM | MAF Agent + Provider 配置；Embedding/Rerank 旁路 |
| `agent` 工具循环 | MAF 工具/函数调用 + 自研编排（HITL/协作等上游特有逻辑） |
| asynq workers | **Hangfire** Jobs / Queues |
| `automation` cron | Hangfire RecurringJob |
| `stream` SSE | ASP.NET SSE；Redis 缓冲按需 |
| docreader gRPC | Grpc.Net.Client |
| `sandbox` / `im` / `datasource` | 后期独立适配，HttpClient/SDK |

## 6. 实施注意

1. **引用 mooSQL / Hangfire.MooSql**：路径对齐 admin 的 ProjectReference 习惯；若 sail-nora 仓独立，在文档中固定相对或 submodule/包源策略（实施时另补）。  
2. **不要**在业务层引入 EF Core 双栈。  
3. **不要**默认再造 asynq；运维面板可对接 Hangfire Dashboard + 自研任务查询。  
4. AI 新能力先走 MAF 扩展点，再下沉到 WeKnora 工具名兼容。  
5. 从 admin 复用代码时：**拷贝范式与精简模块**，避免把 Sailflow/门户无界等无关巨石拖入。
