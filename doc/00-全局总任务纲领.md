# Sail Nora 全局总任务纲领

> 目标：基于腾讯开源 **WeKnora（MIT）** 搭建其**全功能 .NET 版本**。  
> 策略：**C# 重写 Go 主服务与相关 Go 组件**；**前端与 Python 侧保持与上游完全一致**（同源、同契约、可直接复用）。  
> 上游基线：本机对照仓库 `WeKnora-main`，版本 **v0.9.0**（`VERSION=0.9.0`）。  
> 本纲领为 sail-nora 工程的最高层级任务约束；后续分册文档必须服从本文，冲突时以本文为准并修订分册。

---

## 1. 使命与成功标准

### 1.1 使命

在保留 WeKnora 产品能力、部署形态与客户端生态的前提下，将 **Go 单体主服务**（`cmd/server` + `internal/`）及同类 Go 资产（CLI / Go SDK / 桌面壳中的 Go 逻辑等）用 **C# / .NET** 等价实现，使现有 Vue 前端、Python `docreader`（及兼容保留的 `mcp-server`）**无需改造即可对接**。

### 1.2 成功标准（验收硬条件）

| # | 标准 | 说明 |
|---|------|------|
| S1 | **HTTP/SSE/WS 契约兼容** | `/api/v1`、`/health`、`/files`、`/mcp/:endpoint_id`、沙箱 WS 等与上游 Swagger / 实测行为一致；前端零改或仅配置基址 |
| S2 | **鉴权可用且可扩展** | **平台 JWT / 权限 / ApiResult 对齐 sleveen-admin**；WeKnora API Key / Embed / MCP 等产品令牌在平台之上扩展；管理登录与 sync 前端的差异由适配层消化 |
| S3 | **数据面兼容** | PostgreSQL（ParadeDB）迁移语义兼容；可选 SQLite Lite 路径；向量/对象存储可替换策略对齐 |
| S4 | **docreader 契约不变** | 继续以 gRPC 调用上游 Python `docreader`（端口与 proto 同源），不重写解析服务 |
| S5 | **三大能力齐备** | RAG 问答、Agent（工具/技能/沙箱/MCP/HITL/协作）、Wiki 整理均可端到端跑通 |
| S6 | **部署可替换** | Docker Compose 核心拓扑可替换 `app` 镜像为 .NET 进程，frontend / docreader / postgres / redis 保持上游形态 |
| S7 | **许可证合规** | 保留 MIT 声明与第三方声明；溯源 WeKnora 版权与 NOTICE |

**“全功能”定义**：对标上游 v0.9.0 Standard 版能力清单（含可选 profile：Neo4j、MinIO、Langfuse、多向量库等），而非仅 Demo RAG。Lite / Desktop 可作为后续里程碑，但不得在纲领中被默认可砍掉 Standard 能力。

## 2. 范围边界

### 2.1 必须重写（Go → C#）

| 上游路径 | 职责 | sail-nora 落点（均在 `src/` 同名路径） |
|----------|------|------------------------------------------|
| `cmd/server` | 主进程入口 | `src/cmd/server`（ASP.NET Host） |
| `internal/**` | 业务、Agent、模型、路由、中间件、基础设施 | `src/internal/**`（包目录对齐，C# 重写） |
| `cli/` | Go CLI | `src/cli/`（后期） |
| `client/` | Go SDK | `src/client/`（后期 .NET SDK） |
| `cmd/desktop` 中 Go/Wails 逻辑 | Lite 桌面 | `src/cmd/desktop`（后期评估） |
| `cmd/milvus-migrate` 等运维工具 | 迁移辅助 | `src/cmd/milvus-migrate`（按需） |
| `third_party/anydoc-go` 等进程内解析 | Go 侧 Office 解析 | `src/third_party/`；优先 docreader；禁止静默丢能力 |

### 2.2 必须保持一致（不重写 / 同源复用）

| 上游路径 | 约定（同步到 `src/sync/` 同名目录） |
|----------|------|
| `frontend/` | **完全一致** → `src/sync/frontend` |
| `docreader/` | **完全一致** → `src/sync/docreader`；.NET 只实现客户端 |
| `mcp-server/` | 兼容保留 → `src/sync/mcp-server`；主路径内置 MCP（C#） |
| `migrations/` | **语义兼容** → `src/sync/migrations` |
| `config/` | 键名对齐 → `src/sync/config` |
| `dataset/` · `examples/` · `docs/` 等 | 按清单同步进 `src/sync/` |

### 2.3 明确非目标（本阶段不做）

- 用 Blazor / 新前端替换 Vue 控制台  
- 用 C# 重写 `docreader` 解析管线  
- 擅自变更 `/api/v1` 资源模型或 SSE 事件名（除非同步改前端——**禁止**）  
- 为“简化”砍掉 Agent / Wiki / 数据源 / IM / MCP / 自动化等 Standard 能力  
- 绑定单一云厂商、放弃可替换向量库/对象存储设计

## 3. 上游系统心智模型（上下文摘要）

> 完整工程导读见上游 `docs/architecture.md`。以下为 sail-nora 必记结论。

### 3.1 进程拓扑

```text
Clients: Web UI / CLI / Desktop / IM / Embed Widget / 内置 MCP / 外部 SDK
    │
    ▼
app (原 Go 单体 → 现 .NET 主服务) :8080
    ├─ HTTP API + SSE + WS
    ├─ 业务编排 + Agent + RAG Pipeline
    ├─ 任务 Worker（Redis/asynq 语义 或 Lite 进程内）
    └─ 调用 ↓
         docreader (Python gRPC) :50051
         LLM / Embedding / Rerank / VLM / ASR
         Sandbox (Docker / E2B / Cube / Host)
         PostgreSQL|SQLite · Redis · Vector DB · Object Storage · Neo4j?
```

### 3.2 上游技术栈对照

| 组件 | 上游 | sail-nora |
|------|------|-----------|
| 主服务 | Go 1.26、Gin、uber/dig、GORM、asynq | **.NET 8/9+**、ASP.NET Core、DI、EF Core / Dapper、后台队列 |
| 前端 | Vue 3、Pinia、Vite、TDesign | **原样** |
| 文档解析 | Python docreader gRPC | **原样** |
| 主库 | PostgreSQL/ParadeDB 或 SQLite | **同驱动策略** |
| 队列/SSE | Redis + asynq；Lite 内存 | **语义等价实现** |
| 可观测 | Langfuse / OTel | 对齐接入点 |

### 3.3 核心业务链路（必须等价）

1. **入库 Ingest**  
   上传 → 元数据 `processing` → 入队 `document:process` → docparser → chunker → embedding → 检索引擎索引 → 后处理（图谱/多模态/标签/Wiki…）

2. **RAG**  
   `POST /api/v1/knowledge-chat/:session_id`（SSE）  
   流水线事件：`LOAD_HISTORY → MEMORY_RECALL → QUERY_UNDERSTAND → CHUNK_SEARCH_PARALLEL → CHUNK_RERANK → … → CHAT_COMPLETION_STREAM`

3. **Agent**  
   `POST /api/v1/agent-chat/:session_id`（SSE）  
   ReAct 循环 + ToolRegistry（检索/读文档/沙箱/MCP/技能/浏览器/Wiki/记忆等）+ HITL 审批 + 多智能体协作

4. **Wiki**  
   入库触发 `wiki:ingest` / `wiki:finalize`；页面/修订/图谱；前端 WikiBrowser

5. **数据源同步**  
   飞书 / Confluence / GitLab / Notion / RSS / Seafile / 钉钉等 → 同一解析索引链路

### 3.4 API 与路由面（契约锚点）

- 前缀：`/api/v1`  
- 路由分组（上游 `internal/router/routes_*.go`）：  
  `auth_tenant` · `knowledge` · `chat` · `agent` · `mcp_endpoint` · `memory` · `automation` · `infra` · `graph`  
- 路由量级参考（handler 注册点计数，非最终 API 数）：knowledge ~96、infra ~113、agent ~93、auth_tenant ~65、chat ~52 等  
- 契约源：上游 `docs/swagger.yaml` / `website-docs/04-api/`  
- 鉴权顺序与错误码：见上游 API 总览（JWT → API Key → Embed；`TENANT_REQUIRED` 等）

### 3.5 领域服务接口面（移植清单锚点）

上游 `internal/types/interfaces/` 约 50+ 服务接口，移植时作为 **C# 接口/应用服务边界** 的第一版目录，例如：

`knowledge` · `knowledgebase` · `chunk` · `session` · `message` · `agent` · `custom_agent` · `memory` · `mcp_*` · `datasource` · `file` · `vectorstore` · `storagebackend` · `retriever` · `wiki_page` · `automation` 相关 · `audit_log` · `tenant*` · `user` · `stream_manager` · `task_*` 等。

### 3.6 扩展点（.NET 须保留可插拔）

文档解析器（Python 侧）· 分块 · 检索引擎 · 模型厂商 · 联网搜索 · 数据源连接器 · IM 适配器 · Agent 工具 · 存储后端。

## 4. .NET 目标架构（纲领级）

### 4.1 源码布局（已定：全部在 `src/`；只读同步进 `src/sync/`）

仓库根只放 `README.md`、`doc/` 等；**产品源码唯一根为 `src/`**（见 [ADR-0002](./ADR/0002-src目录与上游对齐.md)、[`src/README.md`](../src/README.md)）。

```text
sail-nora/
├── doc/                          # 本仓纲领 / ADR
├── README.md
└── src/
    ├── sync/                     # 无需改造：与上游同名 1:1（已首轮复制）
    │   ├── frontend/ · docreader/ · migrations/ · config/ …
    │   └── …
    ├── cmd/server/               # 重写：ASP.NET Host
    ├── internal/                 # 重写：包目录对齐上游
    ├── cli/ · client/            # 重写（后期）
    ├── docker/ · deploy/ · helm/ # 适配区（非只读默认同步）
    ├── scripts/sync-upstream.ps1
    └── UPSTREAM_VERSION
```

C# 项目挂在重写区目录内；**禁止**改 `src/sync/**` 业务代码。分层职责须可对照上游，禁止大泥球。

### 4.2 技术选型原则（已定，详见 [`doc/.net选型`](./.net选型/00-选型总览.md)）

| 关切 | 原则 |
|------|------|
| 后端范式 | **整体参考 sleveen-admin**（Foundation/System/Host、Scrutor、配置分片）；[ADR-0003](./ADR/0003-dotnet选型与sleveen-admin对齐.md) |
| 运行时 / TFM | **多目标：`net8.0` · `net10.0` · `net11.0`**（ADR-0001）；日常开发可对齐 admin 主力 net10 |
| HTTP / 接口 | ASP.NET Core Controllers；**统一 `ApiResult`** 与 admin 一致；产品 SSE 尽量兼容 `src/sync/frontend` |
| 权限 / JWT | **与 sleveen-admin 一致**（JwtBearer、RefreshToken、`[Permission]`）；产品 API Key/Embed/MCP 另扩展 |
| DI | MS.DI + **Scrutor**；业务用具体 `*Service`，禁止空转发 Impl |
| ORM | **mooSQL.Ext**；表结构优先跑 `src/sync/migrations`；向量侧另接引擎 SDK |
| 任务 / 定时 | **Hangfire + Hangfire.MooSql**（复用主库）；覆盖原 asynq 职责与 cron |
| AI 基建 | **MAF（Microsoft.Agents.AI）**；RAG/工具在其上扩展 |
| 配置 | 分片 JSON（对齐 admin）+ 上游 env 别名；`capabilities` 等产品探测按需保留 |
| 日志/追踪 | 结构化日志 + OTel；Langfuse 钩子对齐 Agent/Pipeline |
| 测试 | 契约/SSE 黄金集 + WebApplicationFactory；平台 API 形状对齐 admin |

### 4.3 Go → C# 映射惯例

| Go | C# |
|----|-----|
| `handler` | Api / Controllers / Endpoint classes |
| `application/service` | Application services |
| `application/repository` | Infrastructure repositories |
| `types/interfaces` | `SailNora.Contracts` / Application 抽象 |
| `middleware` | ASP.NET Middleware + Filters / Policies |
| `router` + `rbac.go` | Endpoint metadata + Authorization handlers |
| `agent` | `SailNora.Agent` |
| `chat_pipeline` | `SailNora.ChatPipeline` |
| `models/providers` | `SailNora.Models` |
| `dig` container | `IServiceCollection` 模块扩展 |
| goroutine + asynq | **Hangfire** Job / Queue |
| 模型调用 / Agent LLM | **MAF** Agent + 工具扩展 |
| GORM | **mooSQL** `MooRepository` / SooRepository |

## 5. 兼容性契约（最高优先级工程约束）

### 5.1 对外契约冻结项

1. URL 路径与 HTTP 方法  
2. 请求/响应 JSON 字段名与类型（含错误 `code`）  
3. SSE 事件类型、顺序语义、续传 `continue-stream`  
4. 鉴权 Header：`Authorization`、`X-API-Key`、`X-Tenant-ID`、Embed/MCP 相关头  
5. 文件代理与预签名 URL 行为  
6. docreader gRPC 方法与消息  
7. 任务类型字符串（如 `document:process`、`wiki:ingest`）  
8. RBAC 角色名与 API Key capability 常量  

### 5.2 允许的内部差异

- 语言、框架、包结构、并发原语  
- 内部日志字段、私有指标名  
- 等价算法的性能优化（须有对比测试）  
- 在 **不破坏契约** 前提下的 .NET 惯用写法  

### 5.3 变更流程

任何疑似破坏兼容的改动：先补契约测试失败用例 → 评估是否可仅后端消化 → **禁止**为图省事改前端。

## 6. 分阶段路线图（总任务拆解）

> 阶段可并行准备，但**对外宣称能力**必须按门禁解锁。每阶段结束产出：可运行产物 + 契约测试报告 + 分册文档更新。

### 阶段 0 — 工程奠基（当前）

- [x] 收集上游架构上下文，形成本纲领  
- [x] 确认 TFM：`net8.0` / `net10.0` / `net11.0`；上游同步：手动或脚本（暂不 submodule）  
- [x] `src/` 分区：`sync/` 只读同步 + 重写/适配区（ADR-0002）  
- [x] 首轮复制无需改造资产 → `src/sync/`（frontend/docreader/migrations…）  
- [ ] 锁定 LICENSE/NOTICE 引入方式；补齐根许可声明  
- [x] 在 `src/cmd/server` 建立多 TFM 解决方案骨架（net8/net10；JWT/mooSQL/Hangfire 接线；health+登录冒烟）  
- [ ] CI 矩阵、容器基础镜像、契约测试脚手架  
- [x] MAF 流式冒烟（W0.7，Placeholder SSE）

### 阶段 1 — 平台底座

- 配置加载（env + yaml 别名）  
- DB 迁移执行器（postgres 优先）  
- 用户/空间/成员/邀请、JWT 登录注册刷新  
- RBAC 与 API Key 门闸  
- `GET /system/capabilities`  
- 对象存储最小实现（Local + 一种 S3 兼容）  
- Redis 连接与 Stream Manager 最小 SSE  

**门禁**：前端可登录、进空间、看到能力门控正确。

### 阶段 2 — 知识库闭环（RAG 最小全链路）

- 知识库 CRUD、文档上传、分块查看  
- docreader gRPC 客户端  
- 分块 + Embedding + 至少一种检索引擎（建议 pgvector/ParadeDB）  
- 文档处理队列 Worker  
- RAG `knowledge-chat` SSE  
- 基础模型提供方（OpenAI 兼容 + Ollama）  

**门禁**：上传文档 → 可检索问答 → 前端引用展示正常。

### 阶段 3 — 检索与知识增强

- 混合检索、重排、多向量后端注册表  
- FAQ、标签、分块编辑/回滚  
- 图像管线 / 多模态 embedding（按上游开关）  
- GraphRAG / Neo4j 可选  
- Wiki ingest 与 Wiki 浏览 API  

**门禁**：知识库设置页与 Wiki 主路径可用。

### 阶段 4 — Agent 主体

- AgentEngine ReAct 循环  
- 核心工具：`search_knowledge` / `read_document` / `list_documents`  
- 自定义 Agent、技能安装与加载  
- 出站 MCP 客户端 + 入站 `/mcp/:id`  
- HITL 审批、会话控制（追加/分叉/回滚）  
- 沙箱抽象（先 Docker 一种）  

**门禁**：前端 Agent 对话主路径 + 工具进度事件对齐。

### 阶段 5 — 生态与自动化

- 数据源连接器（按优先级分批：飞书/Confluence/GitLab/Notion/RSS…）  
- IM 频道回调  
- Embed Widget 发布  
- 长期记忆  
- 自动化计划与通知  
- 多智能体协作  
- 队列运维面板 / 审计日志 / Langfuse  

**门禁**：对标 v0.9.0 功能清单的差异表清零或明确延期项（须写入分册）。

### 阶段 6 — 发行与 Lite

- Compose/Helm 中 `app` 替换为 .NET  
- CLI / .NET SDK  
- Lite（SQLite + 进程内队列）与能力关闭矩阵  
- 桌面壳评估  
- 性能基线、安全加固、升级说明  

**门禁**：对外可发布的替换部署文档与回归报告。
