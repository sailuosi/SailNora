# ADR-0001：目标框架（TFM）与上游资产同步方式

- **状态**：已接受  
- **日期**：2026-11-10  
- **关联**：[`00-全局总任务纲领.md`](../00-全局总任务纲领.md)

## 背景

需确定：

1. sail-nora 后端以哪些 .NET TFM 构建与发布；  
2. 如何把 WeKnora 中保持一致的资产（前端、docreader、proto、migrations 等）引入本仓库。

## 决策

### 1. TFM：多目标 `net8.0` / `net10.0` / `net11.0`

- 库与可执行项目默认 **`<TargetFrameworks>net8.0;net10.0;net11.0</TargetFrameworks>`**。  
- 本地日常开发可任选其一；**CI 须覆盖三者**（至少 Debug 冒烟；Release 构建按里程碑加严）。  
- 容器默认镜像以当时主力运行时为准（优先现行 LTS），并在部署文档注明其它 TFM 的镜像/标签策略。  
- 依赖选型须在三 TFM 上可解析；若某包仅支持较新框架，用多目标条件编译或替换实现，**禁止**静默丢掉 net8 支持除非另开 ADR。

### 2. 上游资产同步：手动或脚本；暂不 submodule

- **当前**：从对照仓库（或上游 release）**手动拷贝**，或使用仓库内 **同步脚本** 拉取/覆盖约定目录。  
- **暂不**使用 git submodule / subtree；待协作与版本钉扎成本上升后再评估。  
- 每次同步应留下可追溯记录（`src/UPSTREAM_VERSION`；可选 `doc/上游对照.md`）。  
- 同步目标位于 **`src/sync/<同名目录>`**（见 ADR-0002）。范围：`frontend`、`docreader`、`migrations`、`config` 等无需改造资产；**不**把上游 Go `cmd/` / `internal/` / `cli/` / `client/` 拷入运行时重写区。

## 后果

**正面**

- net8 覆盖存量 LTS 环境；net10/net11 面向新运行时，避免过早绑死单一 TFM。  
- 手动/脚本同步启动成本低，不强迫全员处理 submodule 工作流。

**代价 / 风险**

- 多 TFM 增加 CI 时间与依赖兼容负担，需 Directory.Build.props 统一约束。  
- 无 submodule 时易出现“口头版本”漂移，必须靠版本记录文件与同步脚本纪律弥补。
